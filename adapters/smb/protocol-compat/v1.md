# FileBelt SMB local protocol compatibility v1

The VFS module talks only to the local GPL bridge. Each request is a
big-endian `u32` length followed by protocol version `u16`, operation `u8`,
opaque mount-session and handle IDs, gateway epoch `u64`, and operation bytes.
The bridge must reject a frame larger than 1 MiB, an unsupported version, or an
unknown operation before dispatch. Operation bytes are specified by the future
Apache VFS contract; this adapter never sends a host path, Samba pointer,
physical locator, database credential, or client password across the boundary.

| FileBelt error | SMB status |
| --- | --- |
| `NotFound` | `NT_STATUS_OBJECT_NAME_NOT_FOUND` |
| `AccessDenied`, `SessionStale`, `GatewayStale` | `NT_STATUS_ACCESS_DENIED` |
| `Conflict`, `LockConflict` | `NT_STATUS_SHARING_VIOLATION` |
| `NameInvalid` | `NT_STATUS_OBJECT_NAME_INVALID` |
| `QuotaExceeded` | `NT_STATUS_DISK_FULL` |
| `Unavailable` | `NT_STATUS_IO_TIMEOUT` |
| `Unsupported` | `NT_STATUS_NOT_SUPPORTED` |
| `Internal` | `NT_STATUS_INTERNAL_ERROR` |

The mapping is intentionally conservative: the core must apply its
existence-hiding policy before returning `NotFound`.

## Samba 4.24.6 ABI evidence

The module's `connect_fn`, `disconnect_fn`, `openat_fn`, `pread_fn`, and
`close_fn` declarations were checked against the official Samba 4.24.6 source
header `source3/include/vfs.h` (`struct vfs_fn_pointers`); that header is
unchanged from the previously admitted 4.24.4 tag. Until the module has
a reviewed C-to-bridge IPC implementation, `openat` and `pread` return
`ENOSYS`; they must not delegate to `SMB_VFS_NEXT_*`, because that would access
the placeholder local share path. Directory enumeration and stat require
Samba-owned `files_struct`/`DIR` lifecycle integration and remain intentionally
unregistered rather than returning fabricated directory handles.
