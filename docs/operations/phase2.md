# Phase 2 Operator Guide

## Support boundary

Phase 2 provides a Docker development/integration topology for the Apache core.
It proves the identity, ACL, namespace, storage, sharing, job, TLS edge, and
restart-reconciliation contracts through the Docker acceptance client. It is not a supported
production deployment and has no HA, PITR, RPO, or RTO commitment. Kubernetes
workloads, NetworkPolicies, migration Jobs, disruption behavior, and minikube
lifecycle are Phase 3 work.

Read the current specifications before operating the stack:

- [Namespace and Authorization](../NamespaceAndAuthorization.md);
- [Interfaces and Capabilities](../InterfacesAndCapabilities.md);
- [Storage and Durability](../StorageAndDurability.md); and
- [Runtime and Deployment](../RuntimeAndDeployment.md).

## Required inputs

- PostgreSQL 18 at the exact admitted digest and four least-privilege database
  roles: migrator, API, I/O worker, and maintenance worker.
- One standards-compliant OIDC issuer, exact issuer URL, client credentials,
  callback/public origins, and one or more exact `(issuer, subject)` tenant
  administrator identities.
- One empty or previously initialized POSIX payload root on a single filesystem
  whose volume/provider supplies required encryption at rest.
- Capability-signing and session/share keyed-digest keysets generated by
  `filebeltctl`, stored as read-only secret files with current and retiring
  generations.
- TLS key/certificate for OxiBelt and, when required, a mounted custom CA
  bundle. Public WebPKI roots remain embedded.
- Optional Apache Iggy at the admitted digest. Omitting it must leave the
  PostgreSQL polling fallback enabled.

Never put secrets directly in `filebelt.toml`, environment variables, image
layers, Compose labels, source control, or diagnostic bundles. Use the typed
secret-file references. The narrow `FILEBELT_*` environment overrides are for
non-secret deployment wiring only.

## First startup

1. Create fresh database and payload volumes with deterministic local names and
   restrictive host access. Do not reuse unrelated directories.
2. Run `roles.sql` as the database owner to create the group roles and grant
   the migrator. Create distinct login credentials that inherit exactly one
   group role.
3. Generate all keysets with `filebeltctl`; mount the API private/current
   material and only the required public/retiring material into each worker.
4. Write the versioned `filebelt.toml` and run `filebeltctl config validate`.
   Treat every warning that prevents validation as a startup blocker.
5. Run `filebeltctl database migrate` once with the migrator role, then run
   `grants.sql` as the database owner to apply the reviewed per-table grants.
   API replicas check compatibility but do not apply migrations.
6. Run the idempotent `filebeltctl tenant bootstrap` with the configured tenant
   UUID and exact administrator identities. API startup fails while the tenant
   is absent.
7. Run the storage startup probe. Do not override failure of exclusive create,
   no-follow handling, ownership/mode, file fsync, directory fsync, or
   same-filesystem atomic rename.
8. Start the I/O and maintenance workers, then the API, then OxiBelt. Start the
   optional Iggy profile before or after FileBelt; correctness must not depend
   on its availability.
9. Verify liveness and readiness independently. Readiness requires compatible
   schema, bootstrapped tenant, usable keys, PostgreSQL, and—where applicable—a
   passing payload probe. Iggy outage is degraded, not unready.
10. Exercise two distinct OIDC users: upload, list, Range download, direct
    share, revoke, version, trash/restore, and session revoke. Verify the second
    user cannot infer an unshared object.

## Configuration invariants

The defaults and accepted envelopes are authoritative in
[Storage and Durability](../StorageAndDurability.md#configuration-safety-envelope).
Validation
also enforces these relationships:

- maximum file size is representable by the chosen chunk size and part count;
- request/body/memory arithmetic cannot overflow platform integer limits;
- a job heartbeat is safely below its lease and retry delay is bounded;
- capability and generation recheck intervals do not exceed 60 seconds;
- public origin, cookie route, reserved fail-closed public route, and OIDC callback agree;
- current and retiring key generations do not collide; and
- quota and low-space thresholds cannot admit more bytes than the storage
  envelope permits.

Changing configuration requires a graceful restart. Do not edit persisted
rows to bypass the validation envelope. A value outside an accepted envelope
requires a reviewed update to the storage specification plus migration and
compatibility analysis in the same pull request.

## Normal operation

### Identity and access

- Use local suspend when an IdP account must be blocked immediately; FileBelt
  does not claim automatic IdP deprovisioning.
- Review failed OIDC validation, session revoke, share use, ACL change, denied
  mutation, and tenant-admin audit events without logging their raw secrets.
- Alert on repeated OIDC-attempt admission limiting. Expired and consumed
  attempts are reclaimed on new login admission, and the active set is bounded.
- Verify transactional ACL/membership generation advances before declaring a
  revocation complete. Iggy may accelerate closure, but the 60-second worker
  recheck is the correctness bound.
- Do not grant a tenant administrator database access as a substitute for a
  FileBelt content ACL.

### Storage and jobs

- Treat the free-space write gate, quarantined payload count, finalized orphan
  age, expired upload backlog, reopened finalization count, terminal job count,
  lease-fencing failures, outbox backlog, and last successful scrub/reconcile
  as operator signals.
- Finalization owns a 120-second lease and heartbeats every 30 seconds while
  hashing. Reconciliation reopens an expired finalization with a new fence;
  repeated reopenings indicate worker or database instability and require
  investigation before retrying large uploads.
- A finalized unreferenced object is expected during commit/recovery and is
  protected for 24 hours. Do not manually remove it.
- Reconciliation removes at most 100 operation temporaries per pass after
  their `.writing` or `.finalizing` file has been inactive for 24 hours. A
  matching symlink, unsafe mode, owner mismatch, or unexpected finalizing
  entry stops cleanup for operator inspection instead of being followed.
- Scrub jobs are admitted in batches of 100 and a payload is not scheduled
  more than once in a 30-day interval. A job may renew its 30-second lease for
  at most six hours before it is failed for bounded retry.
- Deletion is complete only after the deletion-intent state is fenced,
  references are rechecked, the physical object is removed, and PostgreSQL is
  updated. Do not delete from an ad hoc query result.
- Inspect terminal/operator-blocked jobs before using `filebeltctl` retry. Fix
  the cause first; retry remains fenced and idempotent.
- Quarantine preserves evidence. Do not relink, delete, or mark a version lost
  without an explicit operator repair decision and retained audit evidence.

### Iggy

The `filebelt` stream carries versioned topics over 16 tenant/aggregate-keyed
partitions. Event retention is seven days and PostgreSQL publication/dedup
evidence remains 30 days. The publisher idempotently creates a missing stream
or topic with that 16-partition, seven-day topology; it does not treat Iggy as
authoritative state. Published outbox rows and their consumer-dedup rows are
removed in bounded batches after 30 days, and expired capability nonces are
also removed in bounded batches. When Iggy is unavailable, leave it down until
the cause is understood: FileBelt commits and five-second job polling continue.
After recovery, allow the outbox publisher to replay and verify consumer
deduplication. A consumer beyond retention rebuilds from PostgreSQL.

Only the admitted Iggy helper container may have `SYS_NICE`, unlimited
memlock, and its seccomp exception. FileBelt containers retain dropped
capabilities and must not share the Iggy writable volume.

## Key rotation

1. Generate a new key generation with `filebeltctl` and stage it alongside the
   current and retiring generations.
2. Restart verifiers first so every consumer accepts the new public/digest
   generation.
3. Restart issuers to make the new generation current.
4. Retain old capability verification keys for at least 60 seconds, session
   digest keys for seven days, and share digest keys for 30 days. Longer
   configured credential lifetimes require a correspondingly longer overlap.
5. After the overlap and audit review, remove retiring material through an
   audited restart. Never remove an in-use generation to accelerate incident
   cleanup; revoke/fence affected credentials first.

## Quiesced backup and restore procedure

1. Stop new login, mutation, upload allocation, and job admission at the edge.
2. Drain byte streams for the capability/recheck bound. Fence remaining upload
   and maintenance operations.
3. Record the database schema version, tenant/backend IDs, operation watermark,
   key generations, image digests, and configuration checksum.
4. Snapshot PostgreSQL and the payload root while quiesced. Keep their common
   watermark and integrity hashes together.
5. Restore into fresh, explicitly named database and payload volumes. Do not
   overwrite the source volumes.
6. Validate configuration and key availability, run forward migrations if
   required, start maintenance reconciliation, and keep public traffic off.
7. Verify every manifest, physical size, and BLAKE3; inspect quarantine,
   deletion intents, upload sessions, leases, outbox, and audit continuity.
8. Start workers, API, and edge, then repeat the two-user authorization and
   version/share acceptance path before deleting the recovery environment.

Record exact commands, revisions, image digests, timestamps, checksums,
failures, and operator decisions. Backup contents are sensitive user data and
must not become ordinary CI artifacts.

## Shutdown and cleanup

Graceful shutdown removes admission, drains active operations, stops lease
renewal, and leaves durable state for takeover. Test orchestration removes only
the deterministic volumes, networks, containers, archives, and tags it created
after verifying their exact names. Never recursively delete an unresolved
path, the repository root, or a shared Docker volume.

For an incompatible binary, migration, key, route, or data-plane incident,
follow the [Phase 2 rollback runbook](phase2-rollback.md).
